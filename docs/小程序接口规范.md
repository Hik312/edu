# 小程序接口规范（/api/mini/*）

小程序端专用 API。与网页端（`/api/*`）**同服务、同账号、同 token**，只是路径与
取数形态按移动端重新裁过。后端实现：`back_study/app/routers/mini/`，
注册顺序与 tag 见 `app/routers/__init__.py`。

## 0. 与网页端的分工（加接口前先读）

| | 网页端 `/api/*` | 小程序 `/api/mini/*` |
|---|---|---|
| 包 | `app/routers/web/` | `app/routers/mini/` |
| 列表 | 一次全量返回 | 强制分页（pageSize ≤ 50） |
| 首页 | 各域各请求 | `/home` 聚合一次拿齐 |
| 详情 | 图谱自行拉邻居 | 详情直接带 `relatedBrief`（id+标题） |
| 共用逻辑 | `db` / `deps` / `schemas`，两端 import 同一份，禁止各写一份 | 同左 |
| 错误 | `{ok:false,msg}` + 状态码 | 同左 |

**规则**：小程序不得新增裸 `/api/xxx`；网页端不要引用 `/api/mini/*`。
看路径前缀即可判断调用方。

## 1. 通用约定

- **鉴权**：`Authorization: Bearer <token>`，token 由 `/api/mini/auth/login`
  或 `register` 签发（与网页端同一 JWT）。未带/失效 → `401 {"ok":false,...}`。
- **成功**：HTTP 2xx 且 `{"ok": true, ...}`（`ok` 可省略于纯数组场景，但新接口建议都带）。
- **失败**：`{"ok": false, "msg": "人话原因"}`；状态码：凭据错/参数校验失败 `400`
  （main.py 有全局处理器，全项目不用 422）、未登录 `401`、无权限 `403`、
  资源不存在 `404`、冲突 `409`。
- **分页**：请求 `page`（从 1 起）+ `pageSize`（1~50，默认 20）；
  响应 `total` / `page` / `pageSize` / `hasMore`。
- **字段命名**：`camelCase`（`topicPath`、`oneLine`、`relatedBrief`）。

## 2. 端点清单

### 认证（tag：小程序 · 前缀 `/api/mini/auth`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/mini/auth/login` | `{username,password}` → `{ok,token,user}`；凭据错 `400` |
| POST | `/api/mini/auth/register` | `{username,password,displayName?}` → 同上 |
| GET | `/api/mini/auth/me` | 当前用户 → `{ok,user}`；未登录 `401` |

`user`：`{id,username,displayName,role,createdAt}`。

### 首页（`/api/mini/home`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/mini/home` | 一次拿：`stats` + `catalog` + `directions` + `pick` |

- `stats`：`total,known,fuzzy,weak,unmarked,dueToday,dueLearned,fresh,dueTodayPlan,notes,drafts,docs,domains,byCategory,bySubject…`
  （与网页端 `/api/system/stats` 同源 `db.stats()`）
  - **`dueToday` 拆成三个数（2026-10-03）**，别再用它当「今天要做多少」：
    | 字段 | 含义 | 本机实测 |
    |---|---|---|
    | `dueLearned` | 学过的卡排期到了 = 真·到期 | 3 |
    | `fresh` | 从没背过的新卡（没有 nextAt，也永远不会逾期） | 397 |
    | `dueToday` | 兼容字段，**= dueLearned + fresh** | 400 |
    | `dueTodayPlan` | **今天实际要刷几张** = `len(pick) or min(dueToday, 20)` | 20 |
  - 拆分的理由：400 张库里 398 张没标过 → `dueToday` 常年 400，
    而复习队列一次只给 20 张。首页大数字摆 400、点进去只有 20，
    是同一套系统两个矛盾口径。**首页该用 `dueTodayPlan`。**
- `catalog`：`[{id,name,emoji,desc,subjects:[{id,name,emoji}]}]`（data/catalog.js；
  `emoji` 给首页分类卡/科目 chip 当图标）
- `directions`：`[{id,name,desc,keywords,emoji,count}]`（data/directions.js；`count` 现算，
  口径 = 网页端 `/api/directions`，chips 上显示「12」用；`emoji` 是模块网格/条的图标）
- `pick`：今日自选清单的 id 数组（首页 CTA 显示「今日自选 N 张」用；空 = 没挑）

### 掌握度（`/api/mini/mastery`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/mini/mastery` | BKT 分布汇总 → `{ok,summary,params}`，**不回每张卡明细** |

- `summary` = `{total,avgP,events,computed,weak,mid,strong,untouched}`，
  与网页端 `/api/mastery?brief=1` **逐字段相同**：两端都走 `db.mastery_report`，
  阈值（<0.4 薄弱 / <0.8 一般 / 其余扎实）和均值算法只有一份。
  `computed` 是真算过掌握度的张数，其余卡给先验 `p_init`（不代表真的不会）。
  check.js 有一条断言直接比对两个响应的 `summary`，谁各写一遍就会红。
- 为什么单开一个端点：`utils/api.js` 原来打的是裸 `/api/mastery?brief=1`，
  违反本文开头「小程序不得新增裸 `/api/xxx`」那条。2026-11-17 挪进 mini，
  不留 `brief` 参数 —— 这一端永远只要汇总，明细是网页端看板的事。
- **唯一豁免**：`/api/health` 是免鉴权的运维探针（网页端、小程序、DEPLOY.md 的
  验证命令打的是同一个），不属于带调用方语义的数据接口，小程序可以直接打。
  「我的」页用它自证 BASE 指的确实是本项目 —— `framework` 恒 `fastapi`，
  端口上坐着别的服务时它照样回 200 + JSON，这个字段是唯一能看出来的东西。

### 卡包（`/api/mini/cards`）

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/mini/cards` | `page,pageSize,q,subject,domain,dirs,idsOnly` | 分页列表，只返回 brief 字段 |
| GET | `/api/mini/cards/{cid}` | — | 详情全文 + 掌握度 + 相关卡标题 |

- `q`：空格分隔，**全都要命中**（与网页端搜索口径一致，复用 `_search_pool`）。
- `dirs`：方向 id（模块筛，如 `agent`），逗号分隔；与 `subject/q` 叠加过滤。
  筛在**分页截断之前**（口径同 `/api/review/due?dirs=`）。查不到的方向 id → 当没筛。
- `idsOnly=1`：只回 `{ok,total,ids:[…]}`，不分页不带明细 —— 详情页逐张浏览要
  一次拿全模块 id 清单（`cards` 字段不出现）。
- 列表项（brief）：`{id,domain,topicPath,title,oneLine,tags,level,deck,deckId,_custom}`；
  **不带** `mechanism/scene/diagram` 等大字段。
- 详情 `card`：全字段（`mechanism[]、scene[]、why、analogy、interviewQ[]、
  diagram、related[]`…）+ `level`（0~3）+ `relatedBrief:[{id,title}]`。
- `q` 无结果 → `total:0, cards:[]`（不是 404）。

### 复习（`/api/mini/review`）

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/mini/review/queue` | `limit`(1~100,默认按每日目标)、`pick`、`all`、`by`、`dirs`、`domain` | 今日到期队列；`pick=1` 只回自选清单；`all=1` 忽略每日目标给全部到期的 |
| GET | `/api/mini/review/pick` | — | 今日自选清单 → `{ok,today,ids,total}` |
| PUT | `/api/mini/review/pick` | body `{ids:[…]}` | 整体覆盖清单（≤100，后端过滤/去重） |
| POST | `/api/mini/review/{cid}` | body `{level}` | 标记掌握度，立刻调度下次复习 |

- 响应：`{ok, today, total, dueTotal, queue}`。
  - `total` = **本次返回的条数**（受 `limit` 截断）
  - `dueTotal` = **今天全库到期数**（不受 limit 影响）← 2026-10-08 新增
- 队列项：`{id,title,oneLine,domain,topicPath,level,nextAt,overdue}`；
  `overdue:null` 表示今天到期（未超期）。
- `pick=1`：队列 = 今日清单（仍走 `due_list` 全量排序按 id 收窄，字段/顺序与普通
  队列同一套渲染）；**清单空 → `total:0` 空队列**，不退化成普通队列。
  清单跨天自动作废（`db.get_today_pick` 按存的日期判）。
- **注册顺序**：`GET/PUT /review/pick` 必须先于 `POST /review/{cid}` 注册
  （静态段在路径参数前，见 learn.py 注释）。
- `level`：`1` 不会 / `2` 模糊 / `3` 会（SM-2 调度，与网页端同一套规则）；
  非法值 `400`，卡片不存在 `404`。
- 响应：`{ok,id,progress:{…nextAt…}}`。

#### ★ 为什么必须有 `dueTotal` 和 `all=1`（2026-10-08 修的产品死结）

实测：库里到期 **525 张**，而每日目标只有 **20 张**。原实现里：

- 首页摆`dueTodayPlan = 20`，学习页只拉 20 张
- 答完这 20 张 → 页面显示「今日复习完成」，只有「🔄 刷新队列」一个按钮
- **点刷新也没用** —— 那 20 张已经答过，拉回来的还是它们

结果：**剩下 396 张在小程序里没有任何入口能刷到**。用户以为复习完了，实际库里
堆着几百张。这是产品死结，不只是体验瑕疵。

修法两端配合：

| 端 | 做什么 |
|---|---|
| 后端 | 多回 `dueTotal`（全库到期数）；加 `all=1` 忽略每日目标（上限仍 100） |
| 前端 | 答一张 `dueTotal-1`（本地减，不额外发请求）；完成页显示「继续刷剩下的 N 张」 |

★ 前提：**数字必须同源**。后端一次算好 `dueTotal` 给前端，
不要让两端各算一遍 —— 早晚会算出不同值（项目里已因此踩过一次）。

### 今日清单时序（小程序）

```
详情页 → GET /review/pick（进页读清单状态） → PUT 覆盖写（加入/移出）
学习页 → GET /review/pick → 非空则 GET /review/queue?pick=1&limit=100
        → 空则 GET /review/queue（limit 不传 = 按每日目标）
完成页 → 若 dueTotal > 0 → 显示「继续刷剩下的 N 张」
        → 用户点 → GET /review/queue?all=1&limit=100
清单空/清空 → PUT {ids:[]} → 回自动队列
```

## 3. 时序：一次复习

```
launch → GET /me（验本地 token，401 清除）
学习页 → GET /review/queue?limit=20
翻卡   → GET /cards/{id}（懒加载，同卡有缓存不重复请求）
作答   → POST /review/{id} {level} → 队列头出队
队列空 → 显示「今日完成」，可手动 reload 刷新
```

## 4. 版本与变更

- 新端点：**先归包**（web 还是 mini）→ 加进对应 `__init__.py` 的 `ALL`
  → 在本文件追加一行 → 跑 `back_study/scripts/check.js`。
- 改动页面取数形态（如分页参数）需同步改 `miniapp/utils/api.js`
  与本文件，两边不一致以本文件为准。
- 上线换域名：只改 `miniapp/app.js` 的 `BASE`，并在小程序后台配置合法域名（https）。
