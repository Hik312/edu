## ★ 先说清楚一件事：怎么读代码才不算白读

很多人读代码失败，是因为用「读」的方式读代码——从头到尾顺着一行行看，
看到第三屏就忘了第一屏。**换成下面这个方法，才叫「读懂」**：

> ## 三遍法（每一遍都带着问题读）
>
> | 遍数 | 带着什么问题读 | 读到什么程度算够 |
> |---|---|---|
> | **第 1 遍：看形状** | 「这文件整体在干嘛？分几块？」 | 只看**函数名和注释**，**不钻实现**。10 分钟 |
> | **第 2 遍：追一条线** | 「一个请求从进来到出去，经过了哪几层？」 | 只追**一条链路**（比如标记一次复习），别的都跳过 |
> | **第 3 遍：逐行拆** | 「这行为什么这么写？不这么写会怎样？」 | 逐行读**你第 2 遍追过的那条线**，配合精读文档 |
>
> **★ 为什么第 1 遍不许钻实现**：因为「不钻」才能建立全局地图。
> 很多人一上来就啃 1900 行的 `db.py`，读到 200 行就放弃——
> 不是因为难，是因为**还没知道自己在读什么**。

**配套的判断习惯**（比记住任何 API 都重要）：

> 看到不认识的代码，问三个问题：
> ① 这行在**读**什么还是**写**什么？
> ② **删掉/改错**会怎样？
> ③ 注释里有没有写**为什么**？
>
> 这个项目里凡是「为什么这么写」的注释，**都是拿 bug 换的**。
> 读注释的收益远大于读实现——因为**实现你随时能读懂，踩过的坑你不读到就永远重踩**。

### ★★★ 阶段 3 的三个「必须想通」的点

这三点是整个项目最值钱的设计，读懂了你就抓住了这个项目的本质：

**① 「双写」为什么必须在一个 `try` 里**：
进度是**状态**（覆盖式，只留最新），事件是**历史**（追加式）。
知识追踪模型吃的是历史，但进度正确性优先级更高。
所以派生数据（事件、掌握度）写失败**不能让它把请求搞挂**——
你重试一次，进度就多推进一轮（连续「会」本该 1→3 天，重试后直接跳到 8 天），
**状态和他的认知对不上，还没有任何地方提示**。

**② 「转发层」为什么一行算法都不写**：
不是为了偷懒，是为了**可对拍**。
`db.schedule()` 只转发，才能让 `algo/demo.py` 拿同一串评级
喂给不同算法比较。**写成「如果配置是 fsrs 就走 A、否则走 B」，
这个算法就再也测不了了。**

**③ 为什么「筛选必须在截断之前」**：
`due_list` 里方向筛选和 BKT 排序都必须在 `items[:limit]` **之前**。
反过来不会报错——程序正常跑、返回 200——
只是「真正掌握度低的卡已经被 limit 截掉了」，排序等于没排。
> **这类 bug 最可怕的地方是「看起来是好的，只是少了个东西」。**

## 常见误解（回来时先看这里，能省一小时）

| 误解 | 真相 |
|---|---|
| 「先看 `app/main.py` 理解全局」 | main 只做横切（装配/中间件/横幅），**业务全在 router 和 db**。但**读代码顺序**上它该第一个读（它是入口） |
| 「`store/` 是数据层所以最底层，先读它」 | **能力上是反的**。先读 db 的规则，再读它脚下踩在哪 |
| 「BKT 和 SM-2 是新旧替代关系」 | **不是**。时间由调度算法算，顺序由 BKT 排，叠着用 |
| 「FSRS 比 SM-2 好」 | ⚠️ **eval 三者 AUC 都在 0.51≈随机**。只能说「同一条仿真曲线下 FSRS 排期次数少约 20%」，**不能说「对你的学生更好」** |
| 「`Depends` 是装饰器」 | **不是**。装饰器是 `@router.get`；`Depends` 是**参数默认值**的一种写法 |
| 「端点一定要写 `async def` 才像 FastAPI」 | **反了**。本项目 db 层是同步 IO，写 `def` 才对；`async def` 会把事件循环卡死 |
| 「没装 MySQL 是 bug」 | 是**设计**。三处降级都打横幅，`/api/storage` 看得见 |
| 「`ALGO=fsrss` 配错会静默退回 sm2」 | **会直接抛 ValueError**。配置拼错却假装成功比启动失败糟糕得多 |
| 「pyflakes 报 unused import 就能删」 | **假阳性**：再导出（`from . import X` 供别处转引）会被误报。删前 grep 跨模块用法 |
| 「grep 全仓能统计模块引用」 | **必须排除 `.venv`**，否则命中的全是 site-packages 里的同名符号 |

## 接下来该学什么（算法与中间件）

### 算法（按「什么时候用到」排序，不按难度）

| 优先 | 主题 | 项目落点 | 学到什么程度 |
|---|---|---|---|
| ★★★ | **SM-2 → FSRS** | `algo/sm2.py` `fsrs.py` | 能说清 `ef`/`interval`/`reps` 怎么互相影响；为什么「模糊」不清零 `reps`；为什么切算法时旧 `ef` 会被误读 |
| ★★★ | **BKT → DKT** | `algo/bkt.py` | 能手推贝叶斯更新；说清 **slip 和 guess 为什么要分开** —— 这正是手感三档表达不出来的 |
| ★★ | **路径决策 Curriculum** | `core/db.py` 的 `build_graph()` | `related[].kind=prereq` 已是一张先修图，拓扑排序即学习路径；叠 BKT 的 p 做权重 |
| ★★ | **图算法** | `algo/graph.py` 六个 | Louvain 模块度公式为什么要按自环重算分母（已踩过） |
| ★ | **文本与向量** | `agent/qa/retrieval.py` | 分块、embedding、余弦、召回+重排。**别提前学**，是给 RAG 用的 |

### 中间件

| 主题 | 什么时候需要 | 学什么 |
|---|---|---|
| **Redis** ★已接 | 现在 | ① **token 可撤销**（现在签了管不了）② 缓存穿透/击穿/雪崩 ③ 与 JWT 配 refresh token |
| **Celery / ARQ** | AI 精读一章几十秒会阻塞请求 | 任务队列模型、失败重试、**幂等** |
| **SSE** ★已用 | 精读进度要实时推 | **SSE 比 WebSocket 简单得多**。本项目已用 SSE 实现流式问答，值得先读 `agent/qa/runtime.py` |
| **Docker** | 一键起 MySQL + Redis + 后端 | 比现在手工起强太多 |
| **pytest + CI** | 现在只有手工脚本 | 下一个该补的就是它 |

### ⚠️ 三个最容易翻车的点

1. **别提前学 LangGraph**。前五步（粒度 → attempt → BKT → 路径决策 → 诊断）全是
   确定性算法，**普通函数更好测**。过早引编排框架只会把简单事变复杂。
2. **中间件按「解决什么问题」学，别按功能列表学**。Redis 别背五大数据类型，
   先回答「**现在 token 签出去就收不回来，怎么办**」—— 答上来就学会了 80% 的价值。
3. **技术栈单独一行，不要塞进 bullet**。`Maven`/`Git` 不是技术栈。
