## 1. 第 0 天：先把东西跑起来

别急着读代码。**先让它跑起来，因为你后面读的每一行都要能对上一个真实跑着的进程。**

```bash
# 1) 后端（FastAPI，唯一实现）
pip install -r back_study/requirements.txt        # 或 back_study/.venv/Scripts/pip.exe
python back_study/run.py 8080

# 2) 前端（Vite dev server，别用 localhost —— 见架构文档踩坑）
cd web && npm install && npm run dev              # http://127.0.0.1:5173

# 3) 全量校验（后面每改一次代码都会再跑它）
node back_study/scripts/check.js
```

**怎么确认跑对了**（三条都要满足，缺一条就是没起来）：

1. 后端横幅打印 `存储: json` 或 `mysql`。出现 `!! 降级运行` 也要能说清原因——
   这是**故意暴露的**，悄悄降级才是 bug（架构文档 §4）。
2. 浏览器打开 `http://127.0.0.1:8080/docs` 能看到 39 个端点，随便点一个 `/api/health` 能返回 `ok:true`。
3. `check.js` 最后一行是 `ALL CHECKS PASSED`。

**第一天建议做的三件小事**（比读代码更能建立直觉）：

- 在网页上注册一个号 → 在 `/docs` 里用 `/api/auth/login` 拿 token → 拿 token 调 `/api/review/due`
  看返回什么。走完这一遍，"前端那些页面在干什么"立刻就具体了。
- 打开 `data/springboot.js`，随便找一张卡读一遍它的字段。所有业务逻辑都是在喂这份数据。
- 改一张卡的一个字（比如 `oneLine`），刷新页面看它出现在哪。**这一步能让你相信数据是唯一真相源。**

## 2. 五圈阅读法：按数据流读，不要按目录读

按目录从 `back_study/` 开始读，读到第三个文件就会迷路——因为你会看到 `store/`、
`core/`、`app/` 三个互相引用的层，却不知道谁先谁后。**正确顺序是跟着一条数据走。**

### 第 1 圈：数据（30 分钟）

| 读什么 | 看什么 |
|---|---|
| `data/catalog.js` | 分类树：category → subject。导航、筛选、图谱都长在这上面 |
| `data/springboot.js` 里**任意一张卡** | 卡片契约的全部字段（架构文档 §6 有字段表） |
| `back_study/core/db.py:122` `load_source_cards()` | 数据是怎么被扫进来的（自动扫 `data/*.js`，加科目不用改代码） |

**自测**：不看代码，说出一张卡必填哪些字段；`related[].kind` 只允许哪三个值。

### 第 2 圈：业务规则（`core/db.py`，半天）

`core/db.py`（约 820 行）是**整个项目的脑子**，所有"什么时候该复习""图谱怎么连"都在这里。
它不碰 HTTP、不碰 SQL——所以它可以在没有服务器的情况下单独读懂。

按这个顺序读，别从上往下读：

| 顺序 | 函数 | 行号 | 为什么先读它 |
|---|---|---|---|
| 1 | `schedule()` | `db.py:74` | SM-2 简化调度，全项目最核心的 20 行 |
| 2 | `due_list()` | `db.py:575` | 复习队列怎么排序，以及"为什么未标记排在'会'前面" |
| 3 | `build_outline()` / `build_graph()` | `db.py:263` / `db.py:326` | MOC 树与图谱是怎么从卡片算出来的 |
| 4 | `public_user()` / `user_by_name()` | `db.py:672` / `db.py:697` | 用户出口必须脱敏 |
| 5 | `backend()` | `db.py:41` | 存储门面——看懂它才知道"数据到底写到哪了" |

**自测**：一张卡从"未标记"到点三次"会"，`interval` 分别是多少？为什么 `level=0` 不能用 `or 9` 兜底？

### 第 3 圈：存哪（`core/store/`，半天）

看懂 `db.py:41` 的 `backend()` 之后，再看它脚下那一层：

```
core/store/base.py      契约（Store 抽象类 + json_loads/dumps）
core/store/jsonfile.py  默认实现 + 降级目标
core/store/mysql.py     可选实现（含 DDL、全文索引、SQL 队列快路径）
core/store/__init__.py  工厂 + 降级判断（★只读一次，之后不复探）
```

**读这一圈要抓住的一条主线**：`db.py` 只算不存，`store/` 只存不算。
两边靠 `base.py` 的契约连起来——**契约上每一条注释都是拿真 bug 换来的，改动前必读。**

**自测**：现在 MySQL 没起，服务为什么还能用？降级信息从哪两个地方能看见？
（答：启动横幅 + `/api/storage`。）

### 第 4 圈：HTTP 边界（`app/`，1 小时）

后端已经是**单实现**了（零依赖版 2026-09-26 删除），所以这圈很快：

- `app/main.py` — 应用装配、静态挂载、三个异常处理器、**启动横幅**
- `app/routers/*.py` — 8 个域，一个文件一个域
- `app/deps.py` — `current_user()` 依赖注入，所有需要登录的端点都靠它
- `app/schemas.py` — Pydantic 请求/响应模型

**自测**：为什么端点全写同步 `def` 不写 `async def`？
（答：db 层是同步 IO，在 `async def` 里跑会堵死事件循环。）

### 第 5 圈：前端（`web/src/`，半天）

前端铁律是**四层单向依赖**：`view → store → api → client`，不许越层。

```
web/src/api/client.js      axios 实例 + 统一错误码（status===400 是后端约定）
web/src/api/*.js           一个域一个文件，只放请求
web/src/stores/*.js        Pinia，只放状态
web/src/views/**/*.vue     页面，只放渲染与交互
web/src/styles/tokens.css  ★全站设计令牌唯一出处（改配色/字号只改这里）
web/src/config/theme.js    ★图表配色唯一出处
```

推荐读法：挑**复习页** `views/review/ReviewView.vue` 一个页面，
顺着 `ReviewView → stores/learning.js → api/learning.js → client.js` 完整走一遍。
走完这一个，其余十个页面是同一个模子。

**自测**：为什么 `chartBase()` 里 `legend` 必须显式 `show:false`？
为什么 `EChart.vue` 必须在容器非零尺寸时才 `init`？
（两条都在架构文档 §12，都是踩过的坑。）

## 3. 一条请求的完整一生（读完能串起来）

**场景：用户在复习页点「会」。** 跟着它走一遍，五圈就全连上了。

```
① 前端  views/review/ReviewView.vue   点按钮
       ↓
② store  stores/learning.js:52        mark(cid, 3)
       ↓
③ api    api/learning.js:40           markCard() → PUT /api/progress/{cid}
       ↓ client.js                    带上 Authorization: Bearer <token>
═══════════════ HTTP 边界 ═══════════════
④ 路由   app/routers/learning.py:26    Depends(current_user) 先解 token
⑤ 鉴权   app/deps.py:24                security.read_token → db.user_get
⑥ 业务   core/db.py:555  set_level()   → schedule(prev, 3) 算新间隔
⑦ 存储   core/store/*.py  progress_put()  写 MySQL 或 JSON
       ↓
⑧ 响应   新进度记录回前端，卡片从今日队列消失
       ↓
⑨ 下次   GET /api/review/due → db.due_list() → 按 rank 排序重新出现
```

**第 ⑥ 步是全部业务的核心**——就 20 行，决定了"什么时候再见到这张卡"。
要改算法、要接 BKT、要做自适应路径，动的都是这一步。

## 4. 现有算法盘点：已经有什么，简化在哪

| 算法 | 位置 | 现状 | 能升级成什么 |
|---|---|---|---|
| **间隔重复（SM-2 简化）** | `db.py:74` | 会 → 1→3→×ef 天；模糊 → 砍半；不会 → 回 1 天。`ef` 上下限 1.3–2.6 | **FSRS**（现代间隔重复，Anki 已默认）。或保留 SM-2 管"何时复习"，上面叠 BKT 管"会不会" |
| **复习队列排序** | `db.py:575` | 三档 rank：不会(1)→模糊(2)→未标记(0)→会(3)，同档逾期久优先 | 最朴素的 Curriculum Learning；可换成 BKT 预测遗忘概率排序 |
| **文档自动分章** | `importer.py:179` | 五级降级：md `#` → 第X章 → 多级编号 → 序号线 → ~1800 字兜底 | 可换成语义切分（embedding 相似度断点） |
| **关键词抽取** | `importer.py:57` | `pick_keywords()`，词频/规则式 | TF-IDF → TextRank → embedding |
| **知识图谱构建** | `db.py:326` | 从 `topicPath` + `related[]` 构图，前缀折叠 | 加社区发现（Louvain）自动聚类 |
| **图谱布局** | `views/graph/GraphView.vue` | ECharts force（Barnes-Hut 四叉树近似斥力） | 节点上千后要换 WebGL / 预计算布局 |
| **口令哈希** | `security.py:63` | pbkdf2-hmac-sha256，12 万轮，随盐 | 够用。要更强就换 argon2/bcrypt（代价：带 C 扩展的依赖） |
| **令牌** | `security.py:92` | PyJWT HS256，7 天 | 接 Redis 后换**可撤销 token**（现在是签了就管不了） |
| **AI 精读** | `core/llm.py` | 云端 → Ollama 兜底；逐章调用；`think:false` | 接 LangGraph 编排 |

**一句话总结现状**：算法全是"能用、可解释、但很朴素"的实现。
这不是缺陷——**它们都是确定性的、可单测的，正好可以作为将来复杂模型的 baseline。**
上 BKT / FSRS 时你有现成对照，能立刻看出新模型到底好没好。

## 5. 还差什么

完整清单见 `docs/技术架构.md` §9。这里只列**影响学习优先级**的三条主线：

### P0 — 不补就没法往下走

| 缺口 | 为什么卡住后面 |
|---|---|
| **`progress` / `notes` 没有 `user_id`** | 进度和笔记**全局共享**，多账号看到同一份。而 **BKT 是 per-user 的**——没有它就没有真正的自适应 |
| **没有 `attempt` 答题记录** | BKT 的输入就是"每道题对/错的时间序列"。现在只有"手感三档"，信息量不够训练任何模型 |

### P1 — 功能缺口

- 知识图谱没有"路径推荐"（现在只能看，不能说"你下一步该学哪张"）

- 文档精读只有"读"，没有"基于内容出题"
- 前端没有任何自动化测试

### P2 — 工程化

- 只有一份 `test_security.py`（16 项），没有 pytest 体系、没有 CI
- 没有数据库迁移工具（现在靠启动时 `init_schema()` 幂等补表，够用但不可回滚）
- 没有日志/观测（出问题只能看 print）

## 6. 要学什么：算法篇

按"什么时候会用到"排序，不是按难度。**前三个是接下来半年真正要用到的。**

### ① 间隔重复：SM-2 → FSRS ★最优先

- **为什么**：项目的核心体验就是它，而且你已经有一份能跑的实现，改起来立刻见效
- **学到什么程度**：能说清 `ef`（难度因子）、`interval`、`reps` 三者怎么互相影响；
  能解释为什么"模糊"不清零 `reps`
- **进阶**：FSRS 用**记忆稳定性/可提取性**建模，比 SM-2 少 20–30% 复习量。
  它已经有开源实现（py-fsrs），可以直接对比你的 SM-2
- **练手**：给 `db.py:74` 写单测，用固定序列断言间隔；再换 FSRS 跑同一序列，比较总复习次数

### ② 知识追踪：BKT → DKT ★决定"自适应"成色

- **为什么**：EduPath 的定位是**自适应**学习平台。没有 BKT，"自适应"就只是"按你的手感排个序"
- **BKT**（贝叶斯知识追踪）：四个参数 `p_init / p_transit / p_slip / p_guess`，
  每答一题做一次贝叶斯更新。**优点是可解释、参数少、冷启动友好**——适合卡片只有几十张的现状
- **DKT**（深度知识追踪）：LSTM/Transformer 吃答题序列。**需要数据量**，几百张卡几万条记录才划算
- **学到什么程度**：能手推 BKT 的更新公式；能说清 slip（会但做错）和 guess（不会但蒙对）
  为什么要分开——**这两个参数正是"手感三档"表达不出来的信息**
- **练手**：先补 `attempt` 表，攒一周自己的答题数据，用 `pyBKT` 拟合，看它预测的掌握度和你自评差多少

### ③ 学习路径决策：Curriculum / 掌握度排序

- **为什么**：`due_list()` 现在就是最朴素的课程学习（先补漏、再学新）
- **要学**：`related[].kind = prereq` 已经是一张**先修图**——在上面做拓扑排序就是一条学习路径；
  再叠 BKT 的 `p_mastered` 做权重，就是"优先补最薄弱的先修"
- **练手**：给 `build_graph()` 加一个"推荐下一张卡"函数，输入当前掌握度，输出 3 张卡 + 理由

### ④ 图谱与聚类（用到再学）

- 力导向布局：Barnes-Hut 四叉树近似（ECharts 已实现，但你要懂它为什么快、什么时候崩）
- 社区发现 Louvain / Leiden：节点上百后自动分群
- 层次聚类：你已经在做知识框架，把它用在"哪些卡片该合并复习"上

### ⑤ 文本与向量（接 RAG 时再学）

- 分块策略、embedding、余弦相似度、召回 + 重排
- **注意**：这是给"文档精读出题""相似卡推荐"用的，不是给前三个阶段用的。别提前学

## 7. 要学什么：中间件篇

> 你明确说过：**Redis 后期要接**；**另一条 Java 简历线必须保留 MongoDB 与 Kafka**。
> 所以下面分"这个项目要的"和"另一条线要的"两栏。

### 本项目（智径 EduPath，全 Python 线）

| 中间件 | 什么时候需要 | 学什么 |
|---|---|---|
| **MySQL** ★已用 | 已经在用 | 索引、`LEFT JOIN`、事务隔离级别、`DECIMAL` 坑（本项目踩过） |
| **Redis** ★下一步 | 接上就能立刻解决三件事：① **token 可撤销**（现在签了管不了）② 会话/限流 ③ 缓存卡片查询结果 | 五种数据结构各自解决什么问题、`TTL` + 过期策略、缓存穿透/击穿/雪崩、与 JWT 配合做 refresh token |
| **异步任务队列**（Celery 或 ARQ） | AI 精读一章要几十秒，**现在会阻塞请求** | 任务队列模型、结果后端、失败重试、幂等 |
| **SSE / WebSocket** | 精读进度要实时推给前端（现在只能干等） | SSE 比 WebSocket 简单得多，**先学 SSE** |
| **Chroma / 向量库** | 做相似卡推荐、语义出题时 | embedding 存储 + ANN 检索 |
| **Alembic** | 表结构要可回滚时 | 迁移脚本、自动生成 vs 手写 |

### 另一条简历线（Java + Python 混合栈）

| 中间件 | 为什么必须 | 学什么 |
|---|---|---|
| **MongoDB** | 简历要求 | 文档模型 vs 关系模型、**什么时候该用 Mongo 而不是 MySQL**（能讲清这个比会写 CRUD 值钱）、聚合管道 |
| **Kafka** | 简历要求 | 分区/消费者组/offset、至少一次 vs 恰好一次、**用它解决什么真实问题**（别写成"为了用而用"，比如学习行为日志流 → 异步更新掌握度） |

### 通用（两条线都要）

- **Docker / docker-compose**：一键起 MySQL + Redis + 后端，比现在手工起强太多
- **Nginx**：反向代理、静态资源、HTTPS（部署文档 `DEPLOY.md` 里的手工步骤都能被它替掉）
- **CI（GitHub Actions）**：把 `check.js` 和测试挂上去

## 9. 八步推进路线

每一步都给出：**做什么 → 学什么 → 怎么验收**。顺序不能跳，因为后一步依赖前一步的数据。

| 步 | 做什么 | 学什么 | 验收标准 |
|---|---|---|---|
| **1** | 撑知识点粒度 + 给 `progress`/`notes` 加 `user_id` | MySQL 迁移、数据隔离 | 两个账号登录，进度互不可见 |
| **2** | 加 `attempt` 答题记录表与接口 | 事件建模 | 每次复习都落一条记录，能导出时间序列 |
| **3** | 实现 **BKT**（叠 `p_mastered`，**不替换 SM-2**） | BKT 四个参数、贝叶斯更新 | 能用自己攒的数据拟合，预测掌握度与自评相关 |

## 10. 给你的三条学习建议（结合你现在的处境）

1. **算法先跑通再学深的。** BKT 的四个参数，先用 `pyBKT` 跑一遍你自己的数据，
   看到"预测掌握度"和"你的自评"差多少，再回去推公式。**先有直觉再学数学，比反过来快一倍。**
   你一贯的偏好也是这样——要能复述、能自测，不要死记。

2. **中间件按"解决什么问题"学，别按功能列表学。**
   比如 Redis：不要背五大数据类型，先回答"**现在 token 签出去就收不回来，怎么办**"——
   答上来就学会了 Redis 在这个项目里 80% 的价值。

3. **两条简历线分开攒证据。**
   - 项目一（智径 EduPath）：全 Python + 多 Agent + BKT + MySQL/Redis，证据是本仓库
   - 项目二（Java + Python）：必须含 MongoDB + Kafka，**关键是能讲清"为什么这里用 Mongo 不用 MySQL"、
     "为什么这里要上 Kafka 而不是直接写库"**——架构理由比代码量重要

## 12. 常见误解（回来时先看这里，能省一小时）

| 误解 | 事实 |
|---|---|
| "后端有两个实现" | **2026-09-26 已删除零依赖版 `server.py`**，现在只有 `run.py`（FastAPI）一个 |
| "有三端（web + 小程序 + PWA）" | **小程序端 2026-09-26 已整端删除**，现在只有 web |
| "加科目要改三处" | 单文件时代的事实。现在只需改 `data/catalog.js`，`db.py` 自动扫 |
| "`/api/health` 的 `llm` 字段表示 AI 是否可用" | 它的值是 `bool(LLM_API_KEY)`，只表示**云端 key 配没配**。查 AI 可用性一律用 `/api/llm/status` |
| "改了 `config.local.json` 的 `STORE` 就会切换" | **降级判断只在工厂里算一次，之后不复探** → 必须重启后端进程 |
| "`_shot/` 里可以放临时文件" | 它是整目录删的产物目录，放进去会丢 |
| "pyflakes 报 unused import 就能删" | **假阳性**：再导出（`from . import X` 供别处转引）会被误报。删前 grep 跨模块用法 |

更多踩坑见 `docs/技术架构.md` §12（约 30 条，每条都是实际炸过的）。
