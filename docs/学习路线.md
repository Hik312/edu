### 3.1 `backend()` — `db.py:53`

**在干什么**：返回当前用的是哪个存储后端（json 还是 mysql）。

**为什么第一个看它**：所有数据读写最终都落到它选中的后端上。看懂它就知道"数据到底写到哪了"。

**读完你要能回答**：MySQL 没起时它返回什么？→ 降级成 json 后端

### 3.2 `schedule()` — `db.py:104`

**在干什么**：算下一次复习日期。**它自己一行算法都没有**，只做一件事：
`return algo.get().schedule(prev, level, today=today)` —— 转发给当前算法。

**为什么要转发而不是自己算**：换算法只改配置（`ALGO=fsrs`），数据层一行不动。
真正的算法在 `algo/sm2.py:27`。

**★ 这里有个真实踩坑**：算法层的 `schedule(prev, level, today)` 本来就有 `today` 参数，
但**转发层从前没往上带**。结果重放历史事件时每条都被当成"今天"，
9 月 29 号和今天的学习压成同一天，`nextAt` 全落在今天，
**之后所有"逾期天数"排序都是错的**。转发层漏一个参数，下游静默给错结果，比直接报错更难查。

**读完你要能回答**：把 `ALGO` 配错成 `fsrss` 会怎样？→ **直接抛 ValueError，不悄悄退回 sm2**
（配置拼错却假装成功，比启动失败糟糕得多）

### 3.3 算法层实际怎么算 — `algo/sm2.py:27`

**这节要让你搞懂 SM-2 的三个状态分别怎么改间隔**。全项目最核心的 20 行：

| 你点的档位 | 代码做了什么 | 效果 |
|---|---|---|
| **会**（level=3） | `reps += 1`；`interval` 变 1 → 3 → `上一轮 × ef`；`ef + 0.1` | 连着答对，间隔越来越长 |
| **模糊**（level=2） | `interval` **砍半**（但 `reps` 不清零）；`ef - 0.15` | 记得"大概会"不算断档，所以次数不清 |
| **不会**（level=1） | `reps = 0`（连击断掉）；`interval = 1`；`ef - 0.2` | 明天重来 |

`ef`（难度因子）范围 **1.3~2.6**，越大表示这张卡越容易记住。

**读完你要能回答**：一张新卡连点三次"会"，`interval` 是？→ **1 → 3 → 3×2.6≈8 天**

### 3.4 `due_list()` — `db.py:1553`

**在干什么**：算出今天该复习哪些卡，以及**按什么顺序排**。

**排序规则**（`db.py:1607` 一行 `items.sort`）：
```python
items.sort(key=lambda x: (_RANK.get(x['level'], 2), -x['overdue'], x['card']['id']))
#                          ①档位      ②逾期越久越靠前     ③按 id 稳定排序
```

**档位顺序是 `不会(1) → 模糊(2) → 未标记(0) → 会(3)`**（映射表 `_RANK` 在 `db.py:1550`）。
为什么这么排？**先补漏、再学新、最后才是巩固** ——
"不会"的卡再不看就白背了，"没背过"的卡明天开始也不迟。

**★ 三处注释都是真 bug 换来的，读的时候重点看**：

1. **老 bug**：`x['level'] or 9` —— 未标记的 level 是 `0`，在 Python 里 falsy，
   `or 9` 会把它变成 9，于是"从没背过"的整批新卡被排到"已经会了"的后面，
   队列里翻半天见不到新内容。正确写法是 `p.get('level', 0) if p else 0`。
2. **方向筛选必须在截断前**：先按方向过滤全量，再 `items[:limit]`。
   反了就是"先拿满 limit 再丢"，方向卡会被挤出去。
3. **`by=bkt` 排序也必须在截断前**：否则只对取到的前 limit 张排序，等于没排。

**读完你要能回答**：
- 为什么 `level=0` 不能用 `or 9` 兜底？
- 筛选放在 `items[:limit]` 之后会发生什么？

### 3.5 `role_plan()` — `db.py:557`

**在干什么**：把「目标岗位」和「卡片库」对账，算出**缺什么**。

**★ 核心判断：缺口按技能词算，不按科目算。**
注释原话：科目「AI 工程」有卡 ≠ 覆盖了这个岗位要的「向量检索」。
**技能词才是岗位真正的考点，缺哪条说哪条才有用。**

**设计取舍**：这个接口**不碰模型**，纯关键词子串匹配，几十毫秒返回。
刻意的 —— 拉一次模型只为算个覆盖率不划算。

**读完你要能回答**：为什么 `/api/plan` 走同步 `def` 而不 `async`？→ 不碰模型，几十毫秒，没必要占线程池

### 3.6 BKT 掌握度 — `algo/bkt.py:70` `step()`

**在干什么**：已知当前掌握度 `p` 和这次答得对不对，算新掌握度。就这几行数学：

```python
p_correct = p*(1-slip) + (1-p)*guess   # 答对概率 = 真会没手滑 + 不会但蒙对
post = p*(1-slip)/p_correct            # 答对了
post = p*slip/(1-p_correct)            # 答错了
return post + (1-post)*transit          # 最后加「练一次本身也会让人学会」
```

**为什么要拆 slip 和 guess**：`slip` = 会但手滑做错，`guess` = 不会但蒙对。
**这正是"手感三档"表达不出来的信息** —— 三档只告诉你"这次对不对"，
BKT 能告诉你"你是真会还是蒙的"。

**注意 `to_correct()`**（`bkt.py:65`）：三档 → 二值，**只有"会"算对，"模糊"算错**。

**读完你要能回答**：为什么 BKT 不参与"什么时候复习"的计算？→ **它答"掌握没"，不答"何时复习"**。
这是能力边界不是没接上（`eval.py:71` 写死 `_PREDICTORS = ('fsrs','hlr')`）

### 6.1 外部工具：MCP（Model Context Protocol）

**这节要让你搞懂**：问答 Agent 怎么调用"自己进程之外"的工具——连 Github 拉外部学习资源、
在本地沙箱跑代码、联网搜索。**这层是本项目从"只有一个 LangGraph"变成"完整 Agent"的关键。**

**怎么接**：每个 MCP server 是一个独立的 stdio 子进程，走 JSON-RPC。桥接代码在
`agent/mcp.py`：用 `stdio_client` 拉起子进程 → `initialize` 握手 → `list_tools` 拿清单 →
把每个工具包成 langchain `StructuredTool`（动态 pydantic schema，签名+类型提示→入参，docstring→描述）。
因为 client 是 async 而业务运行时是 sync，桥里专门开一条后台线程挂 event loop，用
`run_coroutine_threadsafe` 适配。**任一 server 起不来都只降级、不崩服务。**

| MCP server | 进每轮 QA？ | 干什么 | 实现文件 |
|---|---|---|---|
| `web-search` | ✅ | 360 搜索，免 key，失败返回 `[]` 不抛 | `agent/servers/web_search_mcp.py` |
| `code-exec` | ✅ | 本地 subprocess 跑 Python（超时 10s/上限 30s、输出截断 4k），教学演示用 | `agent/servers/code_exec_mcp.py` |
| `github-resource` | ✅ | **学生问知识点时，除卡片库外再从 Github 拉代码示例 / 学习路线 / 仓库**（token-free 搜仓库；搜代码需 `GITHUB_TOKEN`） | `agent/servers/github_resource_mcp.py` |
| `cards` | ❌ | 造卡能力的 MCP 封装（`generate_card`），属"内容生产"动作 | `agent/servers/cards_mcp.py` |

**为什么 `cards` 不进每轮 QA**：qwen3:8b 在工具一多就选错工具。最终定调 **4 内部 + 3 MCP = 7 个**
进每轮 QA 工具集；`cards` 这个"重动作"默认不进列表，改由导入流程 / 另一个 Agent 直接 import 调用
（`nodes.draft(state)` 复用同一套造卡逻辑，已实测能产出真实卡片）。server 开关在 `agent/mcp_servers.json`。
**读 `mcp/` 的顺序**：`mcp_servers.json`（开关清单）→ `mcp.py`（桥接）→ 任意一个 `servers/*.py`（看 `@mcp.tool()` 怎么写）。

⚠️ **一个 Windows 专属坑**：stdio server 里若再 fork 子进程（如 code-exec 跑 Python），必须显式把
stdin 重定向成 `DEVNULL`，否则子进程会继承 JSON-RPC 的 stdin 管道而卡死——不是代码慢，是管道被占了。

⚠️ **planner 不是死代码，是没写完**：`load_candidates()` / `score_candidates()`（203 行）能跑，
只是唯一调模型的 `write()` 没写。`/path` 页实际用的是 `/api/plan` + `/api/review/due`，跟它无关。

## 7. 三条典型流程：每条流经哪些文件

**这节要让你搞懂**：把前面 6 圈串起来。**这三条是这份文档最该拍照的部分。**
（前端部分从略 —— 只看后端的话，流程从 `api/learning.js` 那一步开始读即可。）

### 流程 A：点"会"，下次什么时候复习（**最该先读懂**）

**在干什么**：你点一张卡的「会」按钮，系统算出这条卡什么时候再出现，并把这次练习记进数据库。
（前端那步从 `PUT /api/progress/{cid}` 开始看即可。）

```
POST /api/progress/{cid}
 └ app/routers/web/learning.py:33   set_progress()
   └ core/db.py:104         schedule()      ← 只是转发
     └ algo/__init__.py:79  get()           ← 按 ALGO 配置取实例
       └ algo/sm2.py:27     SM2.schedule()  ← 算法在这里
   └ core/store/            写 progress + 追加 review_event
     └ core/cache.py:255    Redis 缓存掌握度（没装降进程内存）

下次 GET /api/review/due：
 └ app/routers/web/learning.py:87   review_due()
   └ core/db.py:1553               due_list()    不会→模糊→未标记→会
     └ by=bkt 时叠一层 db.py:1519  sort_by_mastery()
```

**★ 关键理解**：`nextAt`（**时间**）由调度算法算；`p`（**掌握度**）由 BKT 算。
**两者回答不同问题、叠着用，不是二选一。**

### 流程 B：问一句"XX 是什么"

**在干什么**：混合检索找卡片 → 让本地模型组织答案（必要时调 MCP 外部工具增强）→ 自检不合格就重写一轮 → SSE 流式返回。
**react 答完再核对一次引用到的卡**，有错就反问用户要不要改。

```
POST /api/agent/ask（stream:true 走 SSE，**flow / react 都流式**）
 └ app/routers/web/agent.py:89   agent_ask()  ← async def + asyncio.to_thread
   └ agent/qa/runtime.py         retrieval.retrieve()   ← 向量+关键词混合（带缓存）
     └ agent/qa/nodes.py:100     retrieve 节点
     └ agent/qa/nodes.py:150     answer 节点    → 组 prompt → Ollama qwen3:8b
        （流式：ContextVar 把 on_token 传进节点，边生成边往外发）
        └ tools.py               7 个工具（4 内部 + 3 MCP）：
                                 search_cards / card_detail / related_cards / due_today
                                 + web_search / run_python / github_search（外部增强）
     └ agent/qa/nodes.py:166     grade 节点     ← 自检
     └ agent/qa/nodes.py:183     route 节点     ← 不过则回 answer 重写一轮
   ← event: done（答案已出，用户可以接着聊）
   ← agent/verify/runtime.py     校验引用卡（**后台**，kind:'bg' 不占步骤条）
     └ 有错 → event: verify → 前端渲染「字段diff + 确认修正」
                → 用户点了才 POST /api/agent/verify/apply → db.apply_card_patch
```
编排图在 `agent/qa/graph.py:67` `build_qa()`（固定流程）与 `:83` `build_react()`（ReAct）。
**外部工具怎么进来的**：`build_tools()` 在每轮开答前调 `load_mcp_tools()` 把 `web-search` / `code-exec` /
`github-resource` 三个 server 的工具挂上（见 6.1）；`cards` server 不在列表里。

**为什么 flow 也能流式**（原来只有 react 能流）：LangGraph 节点函数**只能收到 state**，
没法多传一个 `on_token` 参数，所以用 `ContextVar` 传递（`nodes.set_token_sink`）；
SSE 层用**后台线程生成 + 队列转发**（同步回调里不能 `yield`）。
实测 444 帧正文、出字跨度 103.67s。★ **流式不改质检**：grade 拿到的仍是完整答案，
没过检照样重写一轮，所以可能看到答案被覆盖重写。

**四个硬约束**（都是用户反馈过或踩过的）：
- **回答里不许出现卡片 id** —— id 只在内部工具链流转
- **没查到就说没查到** —— 空队列也不许当成"卡片库是空的"然后说假话（真踩过）
- 工具靠 `tools.set_current_user()`（ContextVar）拿 user_id ——
  **因为函数签名要给模型看，不能加参数**
- **每个新增 step 必须有收尾帧** —— 漏了的表现是「答案全文都显示了、步骤条还在转圈
  且永不消失」。校验发生在答案**之后**，所以标 `kind:'bg'` 走呼吸点，不占步骤条。

### 流程 C：导入一份 PDF 变成卡片

**在干什么**：解析文档 → LLM 定切分点 → 生成草稿卡 → 查重 → **等人工确认**才入库。

```
DocsView.vue
 └ POST /api/import/doc
   └ core/docparse.py:285        pdf/docx/md 解析 + 图片占位
   └ core/importer.py:271        parse_document()  分章
   └ agent/cards/nodes.py:92     refine   ← LLM 定切分点
   └ agent/cards/nodes.py:226    draft    ← 生成草稿
```

## 8. 算法层速查

## 10. 数据隔离：改任何个人数据代码前必读

**主键定义**（注意是**改主键**，不是"加个列"）：
```
progress  PK (user_id, card_id)
notes     PK (user_id, id)
```

**两个坑**（都踩过）：

1. **光加列不改主键 = 没隔离**。`ON DUPLICATE KEY UPDATE` 判重只看主键/唯一索引。
   主键还是 `(card_id)` 的话，两个用户复习同一张卡**写的还是同一行** ——
   读路径全对，写路径静默吃掉数据。**这是最隐蔽的一类 bug。**
2. **`LEFT JOIN` 的 user_id 条件必须写在 `ON` 里**。放 `WHERE` 会把
   「没标记过」的卡（`p.user_id IS NULL`）一起滤掉 → 未标记的卡从队列消失
   （LEFT JOIN 退化成 INNER JOIN，**不报错、只是变短**）。

**同源规则**：**图缓存绝不存掌握度 level**。节点和边完全由卡片集决定、与用户无关，
而 level 是个人数据 —— 混进缓存就是 A 读到 B 的数据。

**回归脚本**：`python back_study/_verify_isolation.py`（14 项，自动清场）

## 13. 常见误解（回来时先看这里，能省一小时）

| 误解 | 真相 |
|---|---|
| "先看 `app/main.py` 理解全局" | main 只做横切（装配/中间件/横幅），**业务全在 router 和 db** |
| "`store/` 是数据层所以最底层，先读它" | **反了**。先读 db 的规则，再读它脚下踩在哪 |

| "改了 `STORE` 配置就会切换" | **只在工厂里算一次**，之后不复探 → 必须重启进程 |
| "`/api/health` 的 `llm` 字段表示 AI 可用" | 那是 `bool(LLM_API_KEY)`，只表示云端 key 配没配。查 AI 一律用 `/api/llm/status` |
| "`stores/docs.js` 是死代码" | **故意的重复**，文件头注释写明了。改接口要两边看 |
| "`agent/planner/` 是死代码" | **没写完的骨架**。两个函数能跑，`write()` 是 TODO |
