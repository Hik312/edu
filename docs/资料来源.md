# 资料来源清单 —— 哪些仓库能导入来背、怎么导

> 用途：配合「生成 → 题库导入」功能（`/api/import/qa`），把 GitHub 上现成的
> 专业资料变成卡片来背。**资料本身不打包进本仓库** —— 版权上以「你自行
> clone 后上传导入」最稳妥，本页只做导购与格式适配指南。
>
> 清单调研于 2026-11-15，star 数与活跃度经 GitHub API 核实；导入格式对应
> 「生成」页题库导入的三种模式（`md-qa` / `anki-txt` / `obsidian-sr`）。

## 〇、实测（2026-11-15，JavaGuide `docs/cs-basics/` 全量）

用 `importer.parse_qa(fmt='md-qa')` 浅克隆实测（`### 是题` 默认配置）：

| 指标 | 数字 |
|---|---|
| 文件数 | 68 个 md |
| 解析出卡片 | **391 张** |
| 跳过（题面下无内容） | 0 |
| 问句式标题占比 | 32%（其余 68% 是主题式标题如「1.1 操作系统概述」，同样可背） |
| 确定性 | 同文件两次解析 id 完全一致 ✓（重复导入走 upsert 覆盖不翻倍） |

结论：JavaGuide 是**导入成功率最高**的单一来源（Apache-2.0 + `###` 问句
结构规整）；政治/408 的对应仓库建议先导 2~3 个文件预览再全量。

## 五、导入操作路径

1. `git clone --depth 1 <仓库>`（浅克隆足够，只要 md）
2. 打开 **生成** 页 → 切到 **题库导入** 模式
3. 选格式（JavaGuide/CS-Notes → `md-qa` + 「### 是题」）→ 多选文件（可多选
   整个目录的 md）→ 填资料来源 → 解析预览
4. 预览表逐卡勾选（跳过项及原因会列出来）→ 「存为草稿」
5. 草稿缓冲区里补 scene（≥2 条真实场景，发布门槛）→ 发布入库 → 按遗忘曲线背

**格式不匹配怎么办**：同一仓库不同文件的标题层级可能不一样（有的用 `##` 问答、
有的 `###`），换 `题面标题级` 重试即可；答案太长的卡会带「截断」标，超长的
建议直接放弃当卡、改用「文档导入」看章节文本。
