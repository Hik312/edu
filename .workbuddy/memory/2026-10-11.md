## 知识库第二轮：论文区压缩 + 右下角 AI 问答（含一个真 bug 的定位过程）

### ★★ 「PDF 又显示不出来」的根因：`workerSrc` 从没赋值（不是并发 bug，是配置漏了）
`PdfViewer.vue` 里 `import workerUrl from '...?url'` 之后**从没赋给pdf.js**，
而 4.10.38 的 `PDFWorker.workerSrc` 是 getter，没设就`throw new Error(
'No "GlobalWorkerOptions.workerSrc" specified.')`。真浏览器一样挂，只是被
loading 文案盖住很久 → 看起来像「网络慢」。
- **症状识别法**：面板显示「打不开这份 PDF」+ 后面跟着那句英文 → 直接去grep
  `workerSrc`，别怀疑渲染逻辑。
- 修法：`pdfjsLib.GlobalWorkerOptions.workerSrc = workerUrl`（模块顶层，一句）。

### ★ 无头环境（--headless=new）的正确降级入口（读源码确认，不是猜）
`PDFWorker._initialize()` 判断
`if (#isWorkerDisabled || #mainThreadWorkerMessageHandler) _setupFakeWorker()`，
而后者读 **`globalThis.pdfjsWorker?.WorkerMessageHandler`** ——
`pdf.worker.min.mjs` **模块顶层就写了这个全局**
（`__webpack_exports__ = globalThis.pdfjsWorker = {}`）。
→ **在主线程 `await import('pdf.worker.min.mjs')` 即可**，不用碰 new Worker，
也不用动态 import workerSrc。
- 两个走不通的死路：① 传 `disableWorker`（4.x 已删，传了不报错也不生效）
  ② 把 workerSrc 指向坏URL（会走到 `await import(坏URL)` 二次失败）。
- **必须先 await 完再 getDocument**，并发时 pdf.js 读全局还是 null。
- ⚠️ **`navigator.webdriver` 在 `--dump-dom`/`--screenshot` 下是 `false`**！
  实测过。所以判据要留`_shot=1` URL 参数那条，无头验证时手动带上。
- headless 验证链路：`_seed.html` 塞 localStorage → 带 `&_shot=1` 打开 →
  `--virtual-time-budget=55000 --screenshot`。vite build 会**清空 dist**，
  token/引导页要在 build 之后重新生成。

### ★★ renderAll 必须串行化（并发清空 innerHTML → 整篇空白）
`renderAll` 是 async 且中途 await，**两次调用会交错**：A 建好 canvas → await →
B `wrap.innerHTML=''` 把A 的全扔了。触发路径真实存在：`observe(scroller)` 后
ResizeObserver **首次 observe 必立刻回调一次**，200ms 后又调 renderAll。
- 改法：`rendering` 标志 + `pending` 标志（不是排队，排队会积压几十次全量渲染）。
- `renderTask.promise` 的异常要**逐页 catch**：并发被打断时 pdf.js 抛
  "Cannot use the same canvas during multiple render() operations"，
  不接住就中断整个循环，前面画好的页一起作废。
- 加了 ResizeObserver（不是 window.resize）——左栏折叠/问答面板开关改的是
  **容器**宽度，window 尺寸没变，监听 window 永远收不到。

### 上方压缩（用户诉求：论文偏上、竖着多显示）
- `.kb-head` 14px→9px、`h3` fs-lg→fs-md、搜索框 8px→6px
- `.reader-head` 16px→8px、`align-items: flex-start`→`center`、
  `h3` fs-lg→fs-md + ellipsis、`.reader-meta` wrap→nowrap
- `.pdfv-scroll` padding 16→10、页间距 14→10
- 缩放口径加「整页 / 适宽」开关（`fitMode`）。整页模式取
  `min(byWidth, byHeight)`，而不是固定用某一个 —— 单用高度会在宽窗口里太小，
  单用宽度会在矮窗口溢出。

  → 做成开关（默认适宽）。

3. `mode='limit:3'` 解析里 `if ':' in mode` 把 start 也设成 3 →
   「只翻 3 段」变成「从第 4 段起翻 3 段」，前 3 段永不处理，
   **而端点返 200、进度显示「已完成 3 段」，看起来完全正常**。
   → 已改成 `head, _, tail = mode.partition(':')` 互斥解析。
→ **通用教训：批量循环里的 except 必须同时打 stderr**。只在返回值里带 error
  字段是不够的（前端通常不显示），真因被吞掉后无从下手。
  「所有条目都失败」永远要先怀疑代码，而不是当数据问题。
