过程中修掉 6 个真 bug —— 其中 4 个是"看起来像样式问题、实际是逻辑问题"。

### 修的 bug

1. **EChart 在 0×0 容器上 init，力导向图整片空白**（真 bug，真机也会犯）
   `EChart.vue` 的骨架态用 `v-show`（不是 `v-if`），元素在但 `display:none` → 宽高 **0×0**。
   ECharts 把这个尺寸记成画布，`force` 布局把 54 个节点全收敛到原点；骨架撤掉后
   `ResizeObserver` 补了 `resize()`，**但已收敛的力导向位置不会重算** → 画布空白、
   只有几个标签飘在边上。
   修法：`initChart()` 懒初始化 —— 容器拿到非零宽高才 `echarts.init`，RO 回调里
   `if (!chart) { if (initChart()) apply() }`。
   ★ 为什么只有知识图谱中招：柱状/饼图 resize 后会按新尺寸重算，看着就正常。
   这个坑一开始被误判成 "force 的 repulsion / edgeLength 参数不对"，白调半天。

2. **`chartBase()` 的 legend 隐式 `show:true`**
   ECharts 判定画不画图例，看的是 **`legend` 这个键存不存在**，不是里面的 `show` 值。
   所以那段"只想提供样式"的配置，让**每个**用 `chartBase()` 的图都平白长出一个图例 ——
   环形图上表现为一个贴在圆环边上的「■ 未标记 100%」，跟扇区 label 信息完全重复。
   修法：`chartBase()` 里显式 `show: false`；需要图例的图自己写 `show: true`。

3. **`prefers-reduced-motion` 降级只压了 duration，没清 delay**
   `.rise` 是 `animation: rise .44s ... both` + `animation-delay: (gi*4+ii)*34+60ms`。
   `both` 让元素在动画**开始前**停在 `opacity:0`；delay 最长 ~700ms 没被清零 →
   侧栏一屏十几个菜单项里延迟长的整片看不见。
   修法：那条 media query 里补 `animation-delay: 0s`（transition-delay 同理）。

4. **vite dev server 只监听 IPv6**
   `netstat` 显示 `[::1]:5173`，没有 `127.0.0.1:5173`。Node 18+ 把 `localhost` 优先
   解析成 `::1`，浏览器/代理那侧按 IPv4 找就抓瞎 → 控制台刷
   `WebSocket connection to 'ws://localhost:5173/?token=...' failed`。
   ★ 报错的是**热更新通道**，页面本身往往是好的，别误判成前端崩了。
   修法：`vite.config.js` 写死 `host:'127.0.0.1'` + `hmr:{host:'127.0.0.1'}` + `strictPort:true`。

5. **`504 Outdated Optimize Dep`**
   `node_modules/.vite` 是旧的（之后重装过 element-plus / datav）。删缓存重启即可。

6. **MySQL 侧没有 users 表 → 登录 500**（见下）

### MySQL 那三个叠在一起的问题

用户把 MySQL 服务起起来了（之前是 zip 安装无服务），后端真的切到 MySQL 了
（不再是 JSON 降级），然后**登录就 500**：

```
存储    MySQL 127.0.0.1:3306/study_cards · 卡 20 · 进度 0 · 笔记 0 · 文档 1
[api] (1146, "Table 'study_cards.users' doesn't exist")
```

三个独立的漏：

- **建表只在 `dbseed.py` 里跑**，后端启动不建。DDL 加了 users 表，但库是更早建的，
  没人想起再跑一次初始化 → 表一直缺着。
- **`_build()` 的表探测只查 `cards`**。cards 在就判定可用，users 缺了查不出来 ——
  服务正常起、卡片正常看，一直到有人点「登录」才炸，**报错点离原因十万八千里**。
- **`--import-json` 的 `files` 字典里没有 users.json**，账号根本不会搬过去。

修法（三处一起）：
- `core/store/__init__.py` `_build()`：ping 成功后先跑一次 `st.init_schema()`
  （DDL 全是 `CREATE TABLE IF NOT EXISTS`，幂等、只补缺的），失败只警告不拦启动；
  然后把探测改成遍历 7 张必需表，缺哪张就指名道姓地降级提示。
- `scripts/dbseed.py` `cmd_import_json`：加 users 搬运。
  ★ **不能直接 `st.user_put(u)`** —— `user_put` 见到 `id` 就走 UPDATE，
  往空表上 UPDATE 是**静默影响 0 行**，一条也进不去还不报错。
  要按用户名对齐：库里没有就**剥掉 id** 让它走 INSERT（AUTO_INCREMENT 重新发号），
  库里已有才带真实 id 去 UPDATE。
- 已执行 `--sync`（补建 users 表）+ `--import-json`（新增 3 个账号），两版后端登录均 200。

### 新增：`back_study/scripts/smoke_paper.py`

**Python 版**的浏览器冒烟（取代了今天先写的 bash 版 `smoke-paper.sh`，那份已删）。
自包含：起 `server.py` → 登录拿 token 写 `dist/_seed.html` → 逐页抓图 → 收服务。
为什么弃用 bash 版：Git Bash 在这台机器上连着给假信号（详见 skill `headless-web-screenshot`），
最坑的是 `cd X && cmd &` 里的 `&` 作用于**整条列表**，`cd` 也跟着进后台子 shell，
后续命令仍在原目录 —— 这解释了之前反复出现的"日志文件明明写了却读不到"。

用法：`python back_study/scripts/smoke_paper.py --pages dashboard,cards,graph`
（`--pages` 不传默认 4 页；全站 11 页见脚本里的 `PAGES` 表）

★ 种子页必须每次重新生成：`vite build` 会清空 `dist/`，手工放的种子活不过一次构建。
★ 脚本里已把种子生成放在静态自检**之前**，否则每轮都多一条 `/_seed.html 404` 假警报。
