## 接入 MySQL 存储后端（用户：「技术框架有点少，先把数据库加上去吧」）

### 做了什么

把「存哪儿」从 `db.py` 里剥离出来，做成可插拔后端，然后加上 MySQL 实现。

```
core/store/
├── __init__.py   工厂：配置 → 探测 → 建后端；不可用则降级并记原因
├── base.py       契约（读 / 单行写 / 整表替换）+ JSON 工具
├── jsonfile.py   data/store/*.json（默认，也是降级目标，行为与改造前逐字节一致）
├── mysql.py      MySQL 8.0 + pymysql（DDL / 内容同步 / SQL 到期队列）
└── schema.sql    表结构可读版
back_study/config.local.json   本机配置（STORE + 连接信息，已进 .gitignore）
back_study/scripts/dbseed.py   建库建表 / 内容同步 / JSON 存量迁移
```

**db.py 的公开函数签名一个没改**，只换脚下的实现 —— routers 和 server.py 按老名字调，
所以两版后端同时拿到了 MySQL 能力。这条是硬约束：签名一改就得同步改两遍，迟早漏一处。

### 设计取舍（都写进代码注释了，别忘）

1. **谁说了算**：`data/*.js` 是内容（git 管），MySQL 的 `cards` 表只是**查询副本**。
   改了源文件要 `dbseed.py --sync`；指纹不符时 `/api/storage` 报 `stale:true`，
   而且**接口回落到读文件**，不端「源码已改、库里还是旧的」那种版本 —— 那比没数据库更难查。
   指纹用内容 md5（各卡指纹排序后再哈希），所以调换卡片顺序不算内容变化。
2. **降级必须看得见**：缺 pymysql / MySQL 没起 / 表没建 → 全都回退 JSON 照常服务，
   但启动横幅打 `!!` 告警、`/api/storage` 的 `degraded` 写原因。
   悄悄回退最坏的后果是「以为在写库，其实写进了文件」。
3. **热路径走单行写**：`progress_put` / `doc_put` 是单行 upsert；整表 `*_replace`
   只留给「读全量→改→写全量」的列表式调用方（实测接口就是这么写的）。
   `set_doc_ai` 顺手改成只 put 这一份文档，不再重写整个 documents 表。
4. **为什么是 pymysql 不是 SQLAlchemy**：核心查询就一个到期队列，ORM 换来 10MB 依赖 +
   一层要调试的抽象，不划算。纯 Python 驱动 300KB。
5. **表结构**：`cards` 只把要按列查的（category/subject/domain/title）提成独立列，
   `mechanism`/`diagram`/`related` 这些永远整张一起读写的留在 `payload JSON`；
   `progress` 反过来**全标量列** + `next_at` 索引 —— 到期队列就该是一条 SQL。
   还建了 ngram 中文全文索引 `ft_cards`（MySQL 内置分词器，实测可用）。
6. **全文索引暂时不用**：搜索仍走 Python，理由是两个后端的搜索结果必须一字不差，
   20 张卡的规模上不值当为性能冒语义分叉的风险。卡量上千再切。

### 踩到的坑（都是真炸过的）

1. **`banner_lines()` 里 `info = info()`** —— 局部变量遮蔽了同名的模块级函数，
   `UnboundLocalError`。`py_compile` 查不出来，服务起不来才发现。
   （正好印证了用户记忆里那条：Python 改完必须真跑一次。）
2. **`check.js` 的 NaN 陷阱**：服务起不来时子函数写 `return;` → `total += undefined` = NaN，
   而 `if (NaN)` 是假 → **失败的运行会被当成通过**。改成显式 `return 1`，
   并给累加包一层 `add()`：非有限数一律按「失败 1 项」算。
3. **先有鸡先有蛋**：工厂在「库不存在」时会判定不可用并回退 JSON，
   而 `dbseed.py --sync` 恰恰要连上去建库 → 第一次跑永远建不了。
   加 `store_pkg.make_mysql()` 绕开探测；`ping()` 也要换成 `ping_server()`（不带 database，
   否则带库名连接必报 1049）。
4. **DECIMAL 列**：`ef` 取回来是 `decimal.Decimal`，不转 float 的话 `json.dumps` 直接 500。
5. pymysql 连接不能跨线程（FastAPI 把同步端点丢线程池）→ thread-local + `ping(reconnect=True)`。
   单例连接会随机报 `Packet sequence number wrong`。

### 验证

- `dbseed.py --sync`：建库建表 + 20 张内置卡入库，ngram 全文索引建成功。
- `dbseed.py --import-json`：把存量 JSON 搬进库（1 份 15 章文档，`aiDone=10` 保留完整），
  JSON 备份成 `.bak-时间戳`。
- **端到端落库证明**：走接口打 `PUT /api/progress/sb-autoconfig` + `POST /api/notes`，
  然后**绕过应用层直接查 MySQL** —— progress / notes 各 1 行，字段值对得上。
- **降级两连测**：① 端口指到 3999（服务没起）→ 照常服务 + 横幅 `!!` + degraded 写原因；
  ② 指向一个空库（建了库没建表）→ 提示去跑 `dbseed.py --sync`。
- `check.js`：两版各 25 项冒烟全过；**存储一致性段**把同一个服务起两遍
  （`STORE=json` / `STORE=mysql`），20 张卡的到期队列**逐位一致**。
- `wxmlcheck.js`：0 问题，179 个类全有定义。
