## MCP 再加 code-exec 工具（完善）

按之前排序，加了教学价值最高的**代码执行沙箱**。`run_python` 让 QA Agent 能跑代码验证答案/演示算法，从"只检索"升级成"会动手验证"。

新增/改动：
- 新增 `agent/servers/code_exec_mcp.py`：FastMCP 暴露 `run_python(code, timeout=10)`，在**隔离子进程**里跑代码（临时文件 + `subprocess.run`），返回 stdout/stderr；超时上限 30s、输出截断 4000 字符、退出码非0/报错/超时都有明确文案。
- `mcp_servers.json` 加 `code-exec` 条目。
- `agent/qa/tools.py:build_tools()` 的 `max_tools` 由 1 调到 **2**（4 内部 + web_search + run_python = 6）；顶部注释同步改"6 工具下 qwen3:8b 偶有选错但可接受，要更稳调回 1"。`mcp.py` 的 `load_mcp_tools` 默认 `max_tools` 也改成 2。

⚠️ 关键坑（复盘必记）：**stdio MCP server 里再 spawn 子进程，必须显式重定向三路 stdio**。第一版用 `capture_output=True`（只重定向 stdout/stderr，`stdin` 仍继承），结果 `run_python` 一定超时——因为子进程继承了 MCP 的 JSON-RPC **stdin 读端**，在 Windows 下挂起。隔离跑（stdin 是普通管道）完全正常，塞进 stdio 服务才挂，定位花了这一步。修复：`stdin=subprocess.DEVNULL` + stdout/stderr=PIPE + `close_fds=True` + Win 加 `CREATE_NO_WINDOW`。

实测（venv 3.10.11）：`build_tools()` 现返 6 工具；`run_python` 正常代码秒回、超时(2s 跑死循环)→"执行超时"、空代码→"没有收到"、报错→带 traceback 回传，全过。注意项目 venv 没装 numpy，`import numpy` 会 ModuleNotFoundError——正常报错透传，往 venv `pip install` 即可用。

## react 问答内置「卡片校验 / 自纠」（把校验挂进问答流水线，不是独立功能）

**先记一个走错的路**（下次别重犯）：我第一版把校验做成了独立的「校验/自纠」面板按钮，
用户明确否定——他要的是**校验嵌进 Agent 流式问答(react)这条流水线**：RAG检索→联网MCP→验证检索到的卡
→回答→(若有错)反问用户是否改→允许则直接改卡。独立面板是错的。**需求先复述确认再动手。**

最终设计（用户确认：校验引用到的前 2-3 张、每次 react 自动跑）：
- `agent/verify/runtime.py`：`verify_cards(cards)` 逐张联网取证 + **一次批量 LLM 判别所有卡**，
  只返回 `proposed_patch` 非空的（真要改的）；`_judge_batch` + `BATCH_VERIFY_SYS`。
- 落库：先出 `proposed_patch` **绝不自动改**；用户点「确认修正」才调
  `POST /api/agent/verify/apply`→`db.apply_card_patch`；`/verify/revert` 可还原。
- `_sse`(app/routers/web/agent.py)：**先发 `done` 帧**（前端立刻解除「生成中」），
  **再**跑慢的校验，结果作 `event: verify` 帧补发。校验失败全吞，不影响已给出的答案。
- 前端：askStream 解析 `event: verify`→onVerify→挂到该条消息 `m.verify`；
  AskView 气泡内渲染「校验发现可疑 + 字段diff + 确认修正/忽略/还原」。
  chat store 的 `pushAssistant` 加 `verify:null`。

★ 两个实测坑：
1. **批量 vs 逐张**：逐张判别每张卡喂一遍「整卡+联网」给模型（每张 20~60s，3 张近 **5 分钟**，
   聊天没法用）→ 改批量一次调用，实测降到 **60s**（3 卡）。联网仍逐张搜保证每卡有真实证据。
2. **done 帧顺序**：校验放在 done 之前会卡住「生成中」几分钟；必须 done 先发、verify 后补。

## 修 bug：登录 400 前端静默失败（client.js 拦截器不弹提示）

现象：`POST /api/auth/login → 400`，但前端**什么提示都没有**。
根因：`api/client.js` 响应拦截器里非 401 分支的注释写着「其它错误统一弹一次」，
**但代码只 reject、不弹**；而 `LoginView.vue` 的 `catch {}` 恰恰指望拦截器弹 →
登录失败（400「用户名或密码不对」）被完全静默吞掉。
修法：LoginView 自己 catch 并 `ElMessage.error(e.message)`（错误对象已带后端 msg）；
并把 client.js 那句误导注释改成「这层不弹，调用方自己展示」（若全局弹会和
CardsView/GenerateView 等自己弹文案的页面重复）。
★ 全量扫过一遍：只有登录页是这种「空catch + 以为拦截器弹」的写法，其它页面
要么自己弹、要么写进行内错误、要么有意静默。登录 400 本身是设计如此
（auth.py:4，user不存在与密码错返回同一句，防用户名枚举）。本机已有账号
admin / wangtong 等（还有约27 个 check.js 造的 zz_* 探针账号，污染待清理）。

## 两列页面各自独立滚动（生成 / 知识图谱 / 笔记）

用户要「两列模块各加滚动条，滚一列不动另一列」。原来三处都是
`display:grid; align-items:start`，整页一起滚。
做法：根容器 `height:100%`（.content 是 flex:1 有确定高，整条链 html/body/#app 都有
height:100%）+ `align-items:stretch`（去掉 start，否则列按内容高度、整页滚）
+ 每列 `min-height:0; overflow-y:auto`。
- 笔记：左列表头部/搜索/新建固定、只 `.items` 滚（`flex:1;min-height:0`），
  干掉原来的 `max-height:calc(100vh - 320px)` 魔数；右编辑器整列滚。
- 图谱：左画布固定，右侧 `.side-col` 独立滚。
- 生成：两个 `.panel` 各自滚。
★ 只在宽屏生效（min-width 1081/1181px），窄屏单列堆叠保持整页滚，不回归。
★ grid/flex 子项要能滚必须 `min-height:0`，否则内容顶死不滚。
已用无头 Edge + 登录态注入截图验证三页渲染正常（两列底部对齐=stretch 生效）。
