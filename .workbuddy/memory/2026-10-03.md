## 追加一轮：HLR + 评测层 + 首页 + 架构图（用户「都实现」）
### HLR 半衰期回归（algo/hlr.py，新增，已注册）
- 核心两行：留存 R(t)=2^(-t/h)；间隔由 h 反推 `iv = h·log2(1/target)`，不是 SM-2 那种 iv*=ef。
- 2 参数（初始半衰期 H0、目标保留率），**零数据可用**（FSRS 相反：没数据只能硬撑论文权重）。
- 调参踩坑：H0=20/target=0.9 实测 75 次/卡（几乎每天复习）→ 改 H0=35/target=0.85/GROWTH=2.0
  后降到 47 次/卡，间隔 8→11→14→18→24→31 天。
- 切算法的坑：SM-2 的 ef(1.3~2.6) 和 FSRS 的 ef(难度D 1~10) 都落在合法半衰期区间内，
  **数值上区分不了**。兜底用旧间隔反推下限 `h ≥ interval/K`（其他算法靠夹区间，HLR 区间太宽夹不住）。
- 诚实标注：这是 HLR **核心思想的简化式**，不是 Settles & Meeder 论文的 logistic 回归复现。

### 算法评测层（algo/eval.py，新增）
- 指标：同投入下的期末留存/掌握卡数/效率、遗忘次数、logLoss、Brier、AUC、留存率校准曲线。
- **关键 realism 补丁 `_delay()`**：最初假设「用户准时在 nextAt 复习」→ 各算法都把间隔卡在
  「刚好没忘」边界 → 遗忘恒 0、留存恒 90%、AUC 恒 0.5，三个指标同时饱和。加了用户拖延分布后
  才有方差。**教训：评测仿真必须给「实际发生」和「算法预测」之间加噪声，否则量的是算法的自信不是准确度。**
- 另一个修错：期末留存原本用「排出来的间隔」当已过天数（=拿答案考自己），
  应为「最后一次复习 → horizon 实际经过天数」。
- MASTERED_AT 从 0.9 降到 0.7：年末用 0.9 当「已掌握」会让所有算法这列恒为 0（常数列=没这列）。
- 评测结论（300 卡 × 365 天，两 seed 一致）：**FSRS 复习最少/效率最高(0.019)**；
  **HLR 复习最多但期末留存最高(66%)、掌握卡数最多**；SM-2 两头都垫底。
  没有绝对赢家，取决于目标（最少复习量 vs 最扎实）。
- 顺带暴露：FSRS/HLR 的 AUC 都只有 0.50~0.54（接近瞎猜），校准曲线显示**过度自信**
  （预测 0-20% 实际留存 0.69）。这是仿真设定的结果，需真实数据复核。
- 接进 `demo.py --eval`（`--list` 仍比单卡计划）。

## ⚠️ 环境教训：check.js 必须前台跑
用 Bash background 跑 `node check.js` 时，它 spawn 的 uvicorn 子进程会在
background 任务结束时被**连带清理**，导致跑到一半随机 ECONNREFUSED
（一次死在 mini 阶段、一次死在文档阶段，位置不固定），**看起来像代码崩溃其实不是**。
手动单独起服务打同样的端点全部 200。
→ 跑 check.js 用**前台**（`node check.js 2>&1 | tail`，35s 在默认超时内），
   EXIT 才可信。排查「服务中途死了」先怀疑这个，再去查代码。
→ 同理 `npm run build` 偶发 emptyDir/prepareOutDir 失败是 dist 被占用，重跑即可。

### 2. 向量检索：模型早就装了，真正的问题在别处（★ 问答质量提升最大的一处）
- **`nomic-embed-text` 2026-10-03 检查时已装**（0.3GB）—— MEMORY.md 那条
  「未装 nomic-embed-text，仍走关键词降级」**已过时**。检索层代码也早就完整
  （VectorRetriever + HybridRetriever + 余弦 + 索引懒构建 + 自动降级）。
- **根因 1：没加 nomic 的检索前缀。** 该模型硬性要求文档侧 `search_document: `、
  查询侧 `search_query: `，而 `_embed()` 两边共用且都不加 → 查询被编码进文档空间，
  余弦整体失真。症状极有辨识度：**所有卡分数挤在 0.66~0.71、top5 之间差不到 0.05**。
  修法：`_embed(texts, kind='document'|'query')` 分别加前缀；
  **指纹必须跟着升版本**（`v2|...`），否则磁盘上那份没前缀的坏索引
  会被当有效缓存继续用，改了等于没改。
- **根因 2：中文关键词检索用「整串匹配 + 单字兜底」。** 整串在中文几乎永不命中
  → 全靠单字，而单字里混着「是/的/怎」→ **几百张卡全部命中**。
  实测「什么是布隆过滤器」返回「考研英语中非谓语动词如何使用？」（就因为它有「是」）。
  修法：`_STOP_CHARS` 停用词表 + **bigram** 切分（`_terms()`），
  命中才计分（原来单字兜底不看字段、命中就给 1 分）。
- 效果（同一查询前后对比）：
  - 「Redis 为什么快」：LoRA/局部性原理/浏览器渲染（全无关）→ **Redis×5，0.801~0.781**
  - 「TCP 拥塞控制」→ TCP 可靠传输/队头阻塞/TCP 状态
  - 「MySQL 索引为什么用 B+ 树」→ MySQL索引失效场景/执行计划/高性能优化
  - 「HTTP/2 vs HTTP/1.1」→ 精确命中同名卡 + 队头阻塞
- ⚠️ 遗留限制（诚实记录）：**nomic-embed-text 主要英文训练，中文语义弱**。
  「什么是幂等性」这类查询仍会返回 Java 特点这类噪声卡。要根治得上多语言模型
  （bge-m3 / Qwen3-Embedding，~2.2GB，需下载）。当前 hybrid 里向量权重 0.7
  （config.AGENT_VECTOR_WEIGHT），中文为主时值得调低或按语言分流。
- 索引性能实测：首次建索引 ~6~10s（embed 400 张卡），之后走 embeddings.json

## ★ 给 HTML 加「保存为 PDF」按钮（长文档打印的坑）

需求：页面里加按钮能存 PDF。**按钮本身简单，难的是长文档的分页**。

### 坑 1：`.job { page-break-inside: avoid }` 会让每页留半版空白
整份项目块（`.job`）比 A4 一页还高，设了不拆 → 浏览器只能**整块推到下一页**，
于是第 2 页只放一个 job 块、下面全空。**实测 6 页 → 修后 5 页**。
✅ 正确做法：**大块允许拆，只让内部语义小单元保持完整**：
```css
.tp, .bad, .good, .why, .qa, tr { page-break-inside: avoid; }  /* 小的才设 */
li { page-break-inside: avoid; }
.job > .head { page-break-after: avoid; }   /* 只保首尾不孤零 */
```
**通则：`page-break-inside: avoid` 只配给「比一页小」的块。**
判断法：块高 > 页高就别设，设了必然出空白。

### 坑 2：工具栏会被一起打印进去
必须 `@media print { .toolbar, .noprint { display: none !important; } }`。
验证方法（比肉眼看靠谱）：**渲染成 PDF 后用 pymupdf 搜按钮文字**
```python
d = pymupdf.open(pdf)
for i,p in enumerate(d):
    bad = [w for w in ['保存为 PDF','另存为'] if w in p.get_text()]
    print(i+1, '工具栏泄漏' if bad else 'OK')
```

### 坑 3：PDF 文件名会带一长串title
`onbeforeprint` 里改 `document.title` 即可（实测有效）：
```js
var FULL = document.title;
onbeforeprint = function(){ document.title = '智径EduPath-简历项目经历'; };
onafterprint  = function(){ document.title = FULL; };
```
⚠️ 不能在 `onclick` 里先改 title 再 `window.print()` —— Chrome 里无效。

### 顺带加的打印增强（长文档必备）
- `thead { display: table-header-group }` → 表格跨页时**表头每页重复**
- `orphans: 3; widows: 3` → 不留孤行寡行
- `@page { size: A4; margin: 13mm 11mm }` 显式声明
- `print-color-adjust: exact !important` → **Edge/Chrome 默认不打印背景色**，
  深色标题条和绿/红高亮块会全丢，这条是硬性开关
