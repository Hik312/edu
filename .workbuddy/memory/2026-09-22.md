### 换 Python 的关键坑
1. **data/*.js 用单引号，Python json.loads 读不了**
   → 写 tools/normalize-data.js（一次性）转成严格 JSON 字面量，
   保留 `var CARDS_X = [...]` 外壳，网页 <script src> 加载方式不变。
   用 json.JSONDecoder().raw_decode(src, idx) 从 '[' 处直接解析，不用跑 JS 引擎。
2. **normalize 会吃掉文件末尾的 module.exports**（check.js 靠 require() 读卡做校验）
   → 脚本末尾补 `if (typeof module !== "undefined" && module.exports) {...}`，
   浏览器里 module 未定义会跳过，两边都安全。
3. Windows 控制台 GBK → server.py 里 sys.stdout.reconfigure(encoding='utf-8')
4. 用 ThreadingHTTPServer（并发），os.replace 做原子写避免写一半崩坏文件

## 移动端 App 化重做（用户反馈驱动）

用户发来微信里打开的手机截图，三条抱怨：底部导航栏根本没有、样式丑、
「只有看原理，不能做自己的理解、不能导入」。

### 根因（都是真 bug，不是审美问题）
1. **底部标签栏用 `position:fixed;bottom:0` → 被微信内置浏览器自己的工具栏盖住。**
   微信里网页的 fixed 底栏永远在微信工具栏底下。这就是"看不到导航栏"的原因，
   也直接导致用户以为没有笔记/导入两个模块。
2. **整屏高度用 `100vh`。** 移动浏览器里 100vh = 最大视口高度（含被地址栏/工具栏遮的部分），
   拿它当整屏高会把底栏顶到可视区外面。
3. **`.btn.lg` 把 `.btn.main` 的绿底盖掉了。** 两者特异性相同（都是 2 个 class），
   `.lg` 写在后面就赢 → `class="btn lg main"` 得到 panel2 深底 + #0e2b22 深字，
   按钮等于隐形（笔记页"+ 新建笔记"就是这么消失的）。
4. 手机端分类栏是桌面布局硬堆，三条竖着排、每条占满宽 → 就是"丑"的来源。

### 改法
- 底栏改成 **flex 布局里的固定项**（`.app` 是 flex column，tabbar 是最后的 `flex:0 0 auto`），
  不用 fixed。只要 `.app` 高度准确，底栏就永远在可视区内。
- 新增 `--vh` 变量，JS 用 `window.innerHeight` 写入 + resize/orientationchange 监听；
  `body` / `.app` 用 `height:var(--vh,100vh)`。这是移动端整屏布局的正解。
- 加 `.btn.lg.main`（3 个 class，特异性压过 2 个）把绿底钉回来。
- `.btn` 加 `white-space:nowrap;flex:0 0 auto` —— 否则窄屏上"切分成草稿"被挤成三行。
- 列表项改圆角卡片（`#cards` 加内边距、`.item` 去 border-bottom 改成卡片）；
  副标题用 `topicPath.slice(-2)`（"核心原理 · 自动装配"），比笼统的 domain 有信息量。
- 分类栏手机上两行横向滚动（`.catrow{flex-wrap:nowrap;overflow-x:auto}` + 隐藏滚动条）。
- **笔记在手机上是「列表 → 编辑」两屏**（`body.note-focus` 控制），不做左右分栏；
  编辑页顶部返回键复用已有的 `#back`（applyView 里 noteFocus 也显示它）。
- 底栏图标用内联 SVG（Feather 风格 stroke），不引外部字体/图片。

### 新增功能
- **URL 直达**：`?tab=notes` / `?card=xxx` / `?tab=notes&card=xxx`（预关联该卡的新笔记）。
  PWA 快捷方式、分享链接都用得上，也是我能逐个模块截图验证的入口。
- **卡片详情页底部加「我的理解」区块**：列出关联到这张卡的笔记 + 「+ 写我的理解」按钮，
  点了跳到笔记编辑页并自动选中关联卡片。这条链路直接回应用户"没办法做自己的理解"。

## 截图方式更新（重要）：chrome-headless-shell 会挂住不退出
本环境下 `--screenshot` 模式**写完 PNG 但不退出**，前台等它会一直卡到被 SIGTERM 杀掉（连带 kill 整条命令）。
解法：**后台起 + sleep 等文件 + 强杀**：

```bash
CH="C:/Users/wangh/AppData/Local/ms-playwright/chromium_headless_shell-1208/chrome-headless-shell-win64/chrome-headless-shell.exe"
"$CH" --disable-gpu --no-sandbox --hide-scrollbars --window-size=390,900 \
      --virtual-time-budget=7000 --screenshot="C:/Users/wangh/AppData/Local/Temp/x.png" "URL" >/tmp/ch.log 2>&1 &
p=$!; sleep 8; kill -9 $p 2>/dev/null; sleep 1
taskkill //F //IM chrome-headless-shell.exe >/dev/null 2>&1   # 收尾清残留
```
要点：
- 输出 PNG **必须放纯 ASCII 路径**（`%TEMP%`），项目路径含中文会出问题。
- 截图想看到"底部"内容：给 `?card=xxx&mine=1` 这类 URL 配 `scrollIntoView`，或把 `--window-size` 的高度拉大（如 390,2600）当整页图。
- 服务必须与截图写在**同一条命令**里（后台进程不跨调用存活）。

  （同一输入两次，一次全对一次错 4 章）。所以前端改成**逐章调用 + 进度条**，
  后端保留 batch 但加了「字符二元组重合度」对齐质检，低于阈值退回单章重跑。

### 3. 小程序图谱「空心方框」根因（重要）
写死斥力常数 `REP=9000` 是按大画布调的，手机 343×430 上斥力远大于画布尺度 →
**94% 节点被顶到四条边、中心区域 0 个节点、节点互相重叠 9.7px**。量化对比：

| | 中心占比 | 贴边 | 最小净间距 |
|---|---|---|---|
| 写死常数 | 0.00 | 0.94 | -9.7px |
| 动态 k | 0.37 | 0.00 | +14.7px |

三条修复缺一不可：① `k=0.95*sqrt(W*H/n)` 动态理想边长；② 斥力用**平方反比 k²/d²**
（用 k²/d 时斥力量级压过中心回拉，照样顶到边）；③ **不硬夹边**，收尾等比缩放居中铺满。
同样的改法已同步到网页 `index.html` 的 forceStep/fitCanvas。

另外：`<scroll-view scroll-y>` **必须给高度**，小程序 wxss 里 `.gscroll` 根本没有这条规则，
图例/信息栏布局会塌。图谱面板改成 工具条/画布(flex:1)/图例 三段式，
画布放进 `movable-area` + `movable-view`（自带拖动和双指缩放，不用手写手势）。
标签策略：结构节点常显，卡片标签缩放到 1.3× 以上才显（`bindscale` 跨阈值才 setData，防卡）。

## 15:20–15:45 网页美化 + 图谱改 Canvas 粒子场

### 一、图谱：SVG → Canvas 粒子（`index.html` 模块三整块重写，约 430 行）
动机：粒子效果每帧都要变，SVG「一个节点一个 `<g>`」每帧改上百个 DOM 属性，手机上明显掉帧。
现在 `gDraw()` 一次绘制，代价与节点数无关。新的函数分工：
`gStep`(力学) `gFit`(归一化) `gDraw`(绘制) `gStart/gStop`(循环) `gBind`(交互) `gPick`(反变换命中) `selectNode/showGraphSide`(侧栏)。

粒子构成：节点本体（实心圆+左上高光）、外光晕（`glowTex` 预生成贴图 + `lighter` 叠加）、
每节点 5~8 颗小光点绕核心**公转**（轨道 Y 压 0.78 模拟倾斜环）、每条边一颗**流动光点**、
背景尘埃（漂移+一亮一暗）、选中涟漪（两圈相位差 0.5）。

**「在动」的关键**：`gStart()` 的 rAF 循环**不设终止条件**。240 帧后 `G.live = true` 转**静息态**
（力学步长压到 5.5% + 每节点独立相位的呼吸浮动），而不是原来那种 260 帧一到就 `cancelAnimationFrame` 的「咔」一下定死。

本次修掉/避开的坑：
1. **重复绑定监听**：`renderGraph()` 每次切标签都会调用，原来的写法会把 window 监听一份份往上堆
   （拖一次节点触发 N 次 `gMove`，旧闭包还攥着上一批节点引用 = 泄漏）。加 `if (G._bound) return;`。
2. **切走不停帧**：循环永不结束，`switchTab` 里必须 `if (t !== 'graph') gStop();`。
3. **切回来别重排**：记上一轮坐标 `prevPos`，画布尺寸没变就沿用 + `G.frame = 240` 直接进静息态；
   「重置布局」用 `G.W = 0` 让复用失效（比清空 `G.nodes` 稳妥，不会留下空图谱）。
4. **各向异性归一化**：斥力各向同性 → 节点云天然趋圆 → 扁画布(1440×630)/竖画布(390×660)空掉一大半。
   `gFit()` 允许两方向各铺一点，封顶 1.45×（拉过头会挤成一排）。
5. 图例从 JS 内联 SVG 改成 HTML 覆盖层（文字走系统字体，更清楚；且我第一版漏了它，截图才发现）。
6. 光晕贴图按颜色缓存，不能每帧 `createRadialGradient`（60 节点 × 8 粒子 × 每帧 = 几百次，GC 顶不住）。

## 16:35–17:10 后端从 stdlib 迁到 FastAPI（两版并存，契约不变）

### 一、新增了什么
`python run.py [port] [--lan] [--reload]` —— FastAPI 版入口，代码在 `app/`：
`main.py`(装配) / `config.py`(常量+OpenAPI 元信息) / `schemas.py`(Pydantic 请求体) /
`routers/`(system·cards·learning·notes·imports·docs·ai 七个域各一文件)。新增 `requirements.txt`。

**原来的 `tools/server.py` 一行接口逻辑都没删**，保留为零依赖备选：装不了 pip 的场合
（手机、Termux、内网机、借来的电脑）拷过去就能跑。两版共用 `db / importer / llm`，所以数据逻辑
只有一份；风险全在「接口层会不会漂」，于是让 `check.js` 把同一套 21 项冒烟**打在两个实现上**。

### 二、换框架时保住契约的四个点（都踩过或差点踩）
1. **422 → 400**。FastAPI 默认对参数问题返 422，而前端到处是 `if (status===400)`，不改就会静默
   走进「服务器错误」分支。加 `RequestValidationError` 处理器统一映射 400，坏 JSON 单独给话术。
   `HTTPException` 也统一翻成 `{ok:false,msg}`（默认是 `{detail:...}`，前端读不到 msg）。
2. **端点用同步 `def`**。db 层是同步文件 IO，写 `async def` 会卡死事件循环（一个精读请求堵住所有人）。
   FastAPI 见 `def` 自动丢线程池 —— 比旧版无上限 ThreadingHTTPServer 更稳。
3. **静态挂载必须最后**。`app.mount('/', StaticFiles(...))` 吃所有未匹配请求，先挂会把 API 全遮住。
4. **`/api/llm/status` 的 `ok:false` 必须仍是 200**（AI 不可用是正常状态），不能顺手改成 4xx/5xx。

另外 `RequestValidationError` 的 `loc` 里，列表下标是整数、来源段是 `body/query/path`，
拼错误信息时都得剔掉，否则会输出「1: JSON decode error」这种看不懂的东西。

### 三、顺手做的加固
静态目录屏蔽 `tools/` `data/store/` `.workbuddy/` `.git/` —— 手机连着 WiFi 时，浏览器敲
`/tools/db.py` 原来能把源码整个拉走，`/data/store/notes.json` 里还有笔记正文。
比较时**必须转小写**：Windows 文件系统大小写不敏感，`/TOOLS/db.py` 照样读得到。

`socket.connect(('8.8.8.8',80))` 拿到的「出口 IP」就是代理的 fake-ip 段。

**写这个解释器踩的两个坑（都会伪装成「小程序坏了」）**：

## 十、小程序「每个页面都混进别的页面内容」—— hidden 真机失效

### 现象
用户在开发者工具截图：卡片页 / 框架页 / 图谱页**每个页面都混进了别的页面的元素** ——
框架页底部露出图谱的图例、卡片页飘着框架页的「全部展开」按钮、导入页的大输入框压在所有页面上；
各页内容只露出首尾，中间大片空白。

### 根因
**`hidden` 属性在小程序真机上不生效。** 真机 hidden 等价于浏览器 UA 样式
`[hidden]{display:none}`，而 UA 样式优先级输给一切 author 样式。本项目六个 tab 面板
**每一个都带 author display**：`<view class="pv gpv">` 有 `.pv.gpv{display:flex}`；
`<scroll-view class="pv">` 有小程序注入的基础 `display:block`。于是 hidden 被逐一盖掉，
**六个面板同时可见、叠在同一个 `position:absolute; inset:0` 盒子里**
（`.pv` 没有背景色，所以看到的是所有面板内容的混合体）。

**为什么验证工具一直没发现**：`mprender.js:openTag()` 把 hidden 翻译成**内联 style**
（作者样式里优先级最高），所以**截图永远是对的、真机永远是坏的** —— 典型工具说谎。

### 复现（关键一步，别跳过）
把 `_shot/mp-cards.html` 里的 `display:none` 全部抹掉再截图 → 立刻复现用户截图的样子
（导入页 textarea 大框、笔记页按钮、图谱图例全叠上来）。**先确认诊断，再动手改。**

### 修复
1. `index.wxml` 六处：`hidden="{{tab!=='x'}}"` → `class="pv … {{tab!=='x'?'off':''}}"`，hidden 清零。
2. `index.wxss`：`.pvs` 加 `overflow:hidden`；新增 `.pv.off{display:none!important}`
   （作者样式内部 `!important` 才压得过 `.pv.gpv{display:flex}` 和 scroll-view 的基础样式）。
3. 防回归三处：`mprender.js:build()` 扫到 `hidden=` 打警告（渲染器照样隐藏，所以必须显式说出来）；
   `wxmlcheck.js` 新增「真机陷阱」段；`check.js` 在 API 冒烟前也扫一遍。
4. `mprender.js` 另修两处「工具说谎」：① `openTag()` 里「hidden 等价 display:none」的注释是**错的**，
   已改写并标注为「渲染器唯一会说谎的地方」；② `emit()` 给 input/textarea 补
   `<span class="ph">placeholder</span>`，否则搜索框在图里是看不见的空壳、容易误判成「没渲染出来」。
   **注入位置必须在 `VOID_TAGS` 提前 return 之前** —— input 是自闭合标签，写在后面永远走不到
   （textarea 不是自闭合，所以只有它生效过，这个差异一开始把排查带偏了）。
